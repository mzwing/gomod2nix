# Gomod2nix
Convert applications using Go modules -> Nix

## Usage
From the Go project directory execute:
``` bash
$ gomod2nix
```

This will create `gomod2nix.toml` that's used like so
``` nix
let
  pkgs = import <nixpkgs> {
    overlays = [
      (self: super: {
        buildGoApplication = super.callPackage ./builder { };
      })
    ];
  };
in pkgs.buildGoApplication {
  pname = "gomod2nix-example";
  version = "0.1";
  src = ./.;
  modules = ./gomod2nix.toml;
}
```

For more in-depth usage check the [Getting Started](./docs/getting-started.md) and the [Nix API reference](./docs/nix-reference.md) docs.

## Development & tests

Everything is covered by a single sandboxed command:

``` bash
$ nix flake check
```

This builds the package (running the Go unit tests in the sandbox), lints,
checks formatting, verifies that the root `gomod2nix.toml` matches
`go.mod`, and runs the offline end-to-end test suite in `tests/`.

The end-to-end tests are fully offline: synthetic Go modules under
`tests/fixtures/modules` are served through a local `file://` module proxy
(generated by `tests/proxygen.go`), and every test case in `tests/cases`
has a committed golden `gomod2nix.toml` that the generator output is
diffed against. To regenerate a golden file after intentionally changing
generator behavior:

``` bash
$ go build -o /tmp/proxygen ./tests/proxygen.go
$ /tmp/proxygen -out /tmp/proxy example.com/depa@v1.0.0=tests/fixtures/modules/depa ...
$ cd tests/cases/basic
$ GOPROXY=file:///tmp/proxy GOSUMDB=off gomod2nix --dir . --outdir .
```
